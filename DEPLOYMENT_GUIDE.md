Contract: `2.1-r3`. Release status: **local verification candidate; implementation-review owner gates and AWS qualification remain pending**. This delivery contains one combined Python Lambda and additive schema/scripts for the existing identity MySQL database. It does not create a second identity store. Wei creates/configures the AWS resources, private API, S3 bucket and database instance. No AWS provisioning, pilot migration, seed or deployment was executed during development.

## 3. Owner API, storage and permissions handoff

Mount the combined Lambda using the existing private REST API proxy contract, including child paths and all methods. E01 is the existing Team-member DELETE; E02–E63 are in the generated OpenAPI. Preserve existing private ingress, trusted source context and Lambda invoke restrictions. No Function URL, public alternate ingress, body tracing, authorization logging or API response caching. Keep API body limits/timeout known to the client; uploads go directly to S3, never through API Gateway/Lambda.

Admission is a mandatory, unresolved pilot gate: the owner must configure and evidence ingress principal/IP admission plus Gateway method/stage rate/burst throttles. Team Work has no application limiter or application429. Record separate rate/burst values for ordinary reads, mutations, download authorization E17, provider sync E42 and heavy reads E18/E19/E57, plus the actual429 response mapping and retry headers. Method buckets alone are aggregate, not per-user enforcement; identify and test the owner's actual principal/IP mechanism. Reserved concurrency20 is not a replacement. No throttle policy or numeric limit is assumed installed by this guide.

The runtime needs its existing exact identity-secret `GetSecretValue`, the configured provider-secret `GetSecretValue` if enabled, and logging/network permissions already owned by the deployment. Add S3 permissions for this dedicated prefix only: `s3:PutObject`, `s3:GetObject`, `s3:GetObjectVersion`, `s3:AbortMultipartUpload`, `s3:ListMultipartUploadParts`. `CreateMultipartUpload`, `UploadPart` and completion are authorized through PutObject. HeadObject uses GetObject; there is no separate IAM HeadObject action. Do not grant runtime object deletion or bucket listing. If owner-selected SSE-KMS is used, qualify exact encryption-context-scoped `kms:GenerateDataKey` / `kms:Decrypt` permissions and key policy. The cleanup operator separately needs multipart listing, object-version listing/deletion and abort permissions; never give those cleanup grants to Lambda.

Use bucket versioning, blocked public access, TLS and immutable conditional creation with `If-None-Match: *`. The owner must verify bucket policy allows conditional PutObject and CompleteMultipartUpload while allowing the necessary multipart-initiation/part operations. Scope policy to the actual prefix. Configure browser CORS for the actual client origin/method/header set: PUT/POST/GET/HEAD as used, conditional and checksum headers, Content-Type and Content-Length as applicable; expose ETag and checksum/version response headers where the client requires them. Do not replace this verification with a wildcard example policy.

Presigned URLs are bearer capabilities, can be reused until expiry, and do not become instantly invalid when SQL membership changes. New authorization/confirmation is denied after access loss; an already issued capability follows expiry/policy semantics. Conditional writes prevent overwriting an already created key. The service never promises to retract returned bytes or cancel an in-flight transfer. Archive preserves read/download access and is not an authorization-revocation event. The new TTL ceiling applies only to newly issued URLs; upgrading code does not shorten capabilities already issued by an older candidate. A request can continue beyond the URL's start-time expiry; cleanup therefore needs a separately approved quiescence policy and repeated late-arrival sweeps.

Transport selection: files without a declared full-object SHA256 use resumable multipart at100 MiB and above, below S3's single-PUT ceiling; smaller files use conditional single PUT. Declared full-object SHA256 can use single PUT up to5 GiB. Above5 GiB use multipart with verified per-part/composite checksums; supplying a full-object SHA256 in that mode returns422 rather than falsely claiming equivalence. Physical multipart bounds are10,000 parts,5 MiB minimum except the final part,5 GiB maximum part size, and their aggregate object ceiling. This threshold is a transport choice, not a product file-size/count quota.

For multipart: compute each part SHA256 and supply required lowercase-hex checksum_sha256 in its authorization descriptor; missing checksum422. Send the returned x-amz-checksum-sha256 header, and include every part checksum in completion XML. The protocol follows [AWS multipart checksum requirements](https://docs.aws.amazon.com/AmazonS3/latest/userguide/mpuoverview.html); there is no checksum-less multipart fallback. Persist the upload ID locally; authorize parts in paged requests; upload bytes directly; call `complete` with `phase=verify` until verification is complete; call `phase=authorize`, traverse every manifest page and retain its common manifest hash; build CompleteMultipartUpload XML with ordered PartNumber/ETag/checksum entries; send the returned signed POST directly with its required conditional headers. Inspect the entire S3 body even after HTTP200. Finally call `phase=confirm`; Lambda HEAD-verifies the completed version/checksum/length/type and publishes metadata once. Do not ask Lambda to assemble multipart data. After S3 completion409, follow S3's restart semantics with a new upload intent/client UUID, not an unconditional overwrite. Reauthorize only through current permission checks.

Reference documentation: [S3 multipart limits](https://docs.aws.amazon.com/AmazonS3/latest/userguide/qfacts.html), [conditional writes and completion conflicts](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html), [conditional-write bucket enforcement](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes-enforce.html), [presigned uploads](https://docs.aws.amazon.com/AmazonS3/latest/userguide/PresignedUrlUploadObject.html). These describe AWS behavior; local storage doubles are not evidence that the owner bucket complies.
